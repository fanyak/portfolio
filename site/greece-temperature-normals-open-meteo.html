Recreating a Data-Driven Temperature Normal for Greece

Fani Akritidou • 20 min read • Data Analysis

Building a national temperature anomaly chart in Python, with public sector and Open-Meteo data, using cross-validated smoothing.

Note: This post was inspired by Dominic Royé's A data-driven normal for the Spain temperature chart. It is a great article and you should go read it!
Here I recreate the methodology in Python, using data from the recently redesigned National Data Portal.

Setting the Goal

Comparing daily temperature data provides little information about how mean temperatures actually differ between years. What is actually informative is a smooth daily climatological reference, which allows us to compare data without the day-to-day noise. Creating a climatological normal against which we can compare the daily mean temperature is the theme of Dominic Royé's article.

The challenge is to figure out how to smooth a daily climatological reference without either following the noise or flattening real features. This is a model-selection problem where we must choose between families of smoothers. The preferred families for this project are two: loess and harmonic regression. Both of these smoothers can be tuned and (re-)evaluated in a cross-validation process.

The end goal is to recreate Dominic Royé's chart for the daily mean temperature against its climatological normal, only instead of data for Spain I am using data for Greece and instead of R I am using Python.

Tools

To port the original methodology from R to Python I used the following packages:

  • pandas and NumPy for data manipulation
  • Matplotlib and Seaborn for visualization
  • statsmodels for LOWESS/LOESS smoothing and regression
  • scikit-learn for K-fold cross-validation

Load, merge, clean-up, encode

We load the data from each of the .csv files sequentially and merge it into one dataFrame

Code 
              
def load_data() -> pd.DataFrame:
  stations=pd.read_csv('/stations_data/meteo_data/stations_list.csv', header=0, index_col=None)
  station_names=stations['stations'].unique()
  dfs = []
  for name in station_names:
    station_df = pd.read_csv(f'/stations_data/meteo_data/stations_data/{name}.csv', header = 0, index_col=None)
    # add identifier for the source
    station_df.loc[:, 'station'] = name
    # helper for column names
    station_df.columns = pd.Index([colname.replace(" ", "_").lower() for colname in station_df.columns])
    dfs.append(station_df)

  # return new DataFrame with index = (0,...,n)
  return pd.concat(dfs, axis = 0, ignore_index = True)

Next, let's encode the numerical and categorical columns

Code 
              
def encode_data(df: pd.DataFrame) -> pd.DataFrame:
  # Define column groups
  numeric_cols = ["t_mean", "t_max", "t_min", "rh_mean", "rh_max", "rh_min", "prs_mean", "prs_max", "prs_min", "ac_r", "ws_mean", "wg"]
  categorical_cols = ["dwd", "station"]

  # replace '---' with NaN for the entire DataFrame in one go
  df = df.replace('---', np.nan)

  # convert numeric columns and raise error for value that can't be coerced
  for col in numeric_cols:
    if col in df:
      df[col] = pd.to_numeric(df[col], errors='raise').astype(np.float32)

  # convert categorical columns
  for col in categorical_cols:
    if col in df:
      df[col] = df[col].astype('category')

  # convert of date
  df['date'] = pd.to_datetime(df['date'], format="%Y-%m-%d")
  # also add the year as helper
  df.loc[:, ['year']] = df.date.dt.year

  # return sorted by station, date
  return df.sort_values(by=['station', 'date'])

Checking again for all null rows we can see that the combined station data has 9796 rows were all numeric data is missing. Time for a clean-up!
At this point the Panda's pivot method comes in handy. what we want is a frame where we can see the total count of missing values by Year and Station. This is similar to Excel's pivot table. As a summarization of the process I created a heatmap to show which stations stand out as having the most missing values by year.

We can see that Karpenisitown station has missing data for more than 350 days in all years between 2010 and 2017. Livadeia station has missing values for years 2010 through to 2013, and there are a couple of other stations that have missing values for years 2010-2012.

We can't use techniques such as backward / forward filling for the above. We can only drop either the stations or the years. Since Karpenisitown has most of its values missing, I dropped this station entirely from the data. Similarly, since data for Lindos station is missing for the first 3 years (2010-2013), I dropped this station as well.

Lastly, I decided to keep data from 2012 onwards for all other stations, fill forwards and backwards for up to 3 days, and then drop any remaining missing values. The final dataset contains data from 52 stations between years 2012 and 2023, a total of 224603 rows.
