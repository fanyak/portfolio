Recreating a Data-Driven Temperature Normal for Greece

Fani Akritidou • 20 min read • Data Analysis

Building a national temperature anomaly chart in Python, with public sector and Open-Meteo data, using cross-validated smoothing.

Note: This post was inspired by Dominic Royé's A data-driven normal for the Spain temperature chart. It is a great article and you should go read it!
Here I recreate the methodology in Python, using data from the recently redesigned National Data Portal.

Setting the Goal

Comparing daily temperature data provides little information about how mean temperatures actually differ between years. What is actually informative is a smooth daily climatological reference, which allows us to compare data without the day-to-day noise. Creating a climatological normal, a "normal year" curve, against which we can plot a year's values is the theme of Dominic Royé's article.

The challenge is to figure out how to create such a smooth curve out of noisy data, without either following the noise or flattening real features. This is a model-selection problem where we must choose between families of smoothers. The preferred families for this project are two: loess and harmonic regression. Both of these smoothers can be tuned and (re-)evaluated in a cross-validation process.

The end goal is to recreate Dominic Royé's chart for the daily mean temperature against its climatological normal, only instead of data for Spain I am using data for Greece and instead of R I am using Python.

Tools

To port the original methodology from R to Python I used the following packages:
  • pandas and NumPy for data manipulation
  • Matplotlib and Seaborn for visualization
  • statsmodels for LOWESS/LOESS smoothing and regression
  • scikit-learn for K-fold cross-validation
  • openmeto to get the data for the year 2025
  • asyncio for executing coroutines

At this point the Panda's pivot method comes in handy. what we want is a frame to show the total count of missing values by Year and Station. This is similar to Excel's pivot table. As a summarization of the process I created a heatmap to show which stations stand out as having the most missing values by year.

Karpenisitown station has missing data for more than 350 days in all years between 2010 and 2017. Livadeia station has missing values for years 2010 through to 2013, and there are a couple of other stations that have missing values for years 2010-2012.

We can't use techniques such as backward / forward filling to remedy these. We can only drop either the stations or the years. Since Karpenisitown has most of its values missing, I dropped this station entirely from the data. Similarly, since data for Lindos station is missing for the first 3 years (2010-2013), I dropped this station as well.

Lastly, I decided to keep data from 2012 onwards for all other stations, fill forwards and backwards for up to 3 days, and then drop any remaining missing values.

The final dataset contains data from 52 stations between years 2012 and 2023, a total of 224603 rows. This will be the Reference Set.

Since I only need the daily mean temperature records, the rest of the numeric columns can be dropped. Additionally, I created 2 more helper columns, day(1 to 366 to account for leap years) and month (name of the month). These will help with the computations of daily climatology and chart design.
