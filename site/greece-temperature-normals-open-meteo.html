Recreating a Data-Driven Temperature Normal for Greece

Fani Akritidou • 20 min read • Data Analysis

Building a national temperature anomaly chart in Python, with public sector and Open-Meteo data, using cross-validated smoothing.

Note: This post was inspired by Dominic Royé's A data-driven normal for the Spain temperature chart. It is a great article and you should go read it!
Here I recreate the methodology in Python, using data from the recently redesigned National Data Portal.

Setting the Goal

Comparing daily temperature data provides little information about how mean temperatures actually differ between years. What is actually informative is a smooth daily climatological reference, which allows us to compare data without the day-to-day noise. Creating a climatological normal, a "normal year" curve, against which we can plot a year's values is the theme of Dominic Royé's article.

The challenge is to figure out how to create such a smooth curve out of noisy data, without either following the noise or flattening real features. This is a model-selection problem where we must choose between families of smoothers. The preferred families for this project are two: loess(locally weighted regression) and harmonic regression. Both of these smoothers can be tuned and (re-)evaluated in a cross-validation process.

The end goal is to recreate Dominic Royé's chart for the daily mean temperature against its climatological normal, only instead of data for Spain I am using data for Greece and instead of R I am using Python.

Note: the original article used historical data for the years 1961-1990, downloaded from Open-Meteo, as the reference set. This project is (partly) an exercise in using data from the National Portal, where the historical data that is available starts in 2010 and ends in 2023. I used this set as the reference and downloaded the data for 2025 from Open-Meteo (as was done in the original article).

Smooth the Curve

Next step is to select a smoothing function. This is a model selection task where we need to find the member of a family of smoothers the best predicts unseen data. We do that using cross-validation.

As in the original article, the 2 smoothers that I evaluated are Harmonic Regression and Locally weighted regression

Harmonic Regression

As Dominic Royé explains:

Harmonic Regerssion models the climatological curve as a sum of sine/cosine pairs with a 366-day period.

The sum of the sine/cosine pairs are linear predictors, as in OLS. An instance of this model takes two parameters:

  • K, which represents the harmonic order (e.g., 1 for 1st harmonic, 2 for 2nd, etc).
    The higher K is, the less smoothing we get, and the higher the variance of the model.
  • period, the period of the cycle. In our case, period is fixed at 366 days to account for leap years.

While period is fixed, parameter k is a hyperparameter that we need to tune in order to create the model that best predicts the 2025 data.

Again, from the original article:

To pick K we fit on the daily data directly (not an already-aggregated climatology), using k-fold cross-validation split by year, so a given year's 365/366 days stay together, fully in training or fully in test.

For each chosen value of K we repeat the following process n_split times:

  1. create a new OLS model for the selected K order,
  2. hold out the days of the current iteration's test fold years,
  3. fit the model on the days of the training folds,
  4. use the fitted model to predict the held-out days,
  5. estimate the model's error of the nth iteration using the RMSE loss function.

Finally, the estimated performances (RMSE) of all the n_split iterations are used to calculate the estimated average (mean) performance for each K.

Locally weighted regression

Loess works locally, meaning that to make an estimate of a value it uses a fraction of the data that is near-by that value. The size of the fraction is a (hyper)parameter of the model.

Specifially, in the statsmodel package( statsmodels.api.nonparametric.lowess ) this parameter is named frac:

Suppose the input data has N points. The algorithm works by estimating the smooth y_i by taking the frac*N closest points to (x_i,y_i) based on their x values and estimating y_i using a weighted linear regression. The weight for (x_j,y_j) is tricube function applied to abs(x_i-x_j).

To run the Loess regression we use the climatology data (one summarized value per day for all the years), not the raw daily data. However, since the model uses the frac*N closest points we have to make day 366 and day 1 be neighbours. To fix this we glue three copies of the climatology end to end, smooth the concatenated data, and keep only the middle copy
